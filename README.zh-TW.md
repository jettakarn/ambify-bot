Webhook 跑在 Apps Script 上。回覆留在聊天裡。班表會經過 LINE、Gemini 和你的 Google 雲端硬碟。

# 簡介

一個官方帳號共用一份目前班表。管理員上傳 PDF。其他人用員工編號查班。

+ **查班列出今天和之後的班。** 下週班表還沒讀到時，會寫可能人事主管還沒發，或管理員還沒更新，最快本週二出來。丟換班列出今天之後的班。排行榜只列當月，並寫出已讀日期的起訖。
+ **用編號查，暱稱只顯示。** 暱稱寫在編號旁邊。查詢只用員工編號。
+ **Apps Script 就是 webhook。** 讀完的班表放在你的 Google 雲端硬碟。

# 功能

- 管理員傳 PDF。機器人先回已收到，在背景讀完後再傳員工名單。通常不用一分鐘。
- 任何人輸入員工編號，例如 `12345`，就會拿到這個人今天和之後的班次。每一班前面是 `TC` 或 `FL`，只寫上下班時間。下週班表還沒讀到時，回覆會寫可能人事主管還沒發，或管理員還沒更新，最快本週二出來。
- 位元組相同的 PDF 不會重讀。管理員事後補讀的較早週次不進查編號和丟換班。查編號列出今天和之後的班。丟換班看最靠近今天的那一週，下一週已讀過就一起算，並列出今天之後的班。排行榜把當月已讀過的週次都算進去，寫出起訖，其他月份不列。
- 每個檔案請壓在 15MB 以內。免費的 Gemini 額度用完時，回覆會直接寫原因。
- 在 LINE 後台設圖文選單，按鈕送出 `排行榜`、`丟換班` 和 `今日班表`。機器人把這三個字串當成選單。

### 工時

以台北時間的自然月計算。每班先算起迄時數，未滿 9 小時扣 0.5 小時，達 9 小時扣 1 小時。扣完小於 0 就當 0。跨過午夜的班整段落在上班那天的月份，午夜之後的分鐘也算在那個月。

排行榜只列台北時間的當月。當月已讀過的每一週都算。回覆寫出該月第一個已讀日和最後一個已讀日。其他月份不列。沒讀到的日期不補。

訊息上方是自己的時數與名次。下面只列當月前五名的名字。

### 丟換班

機器人列出誰能接你今天之後、在這份班表上的某一班，下一週已讀過就包含下一週。今天和今天以前的班不列入。今天之後只有一班就直接用。有多班會再讓你點要丟的那一班。沒有就回「今天之後沒有可丟的班。」

對方要同時符合這三項：

- 丟出日當天完全沒有排班。跨日班若時間落在這一天，也算有班。
- 與前一日下班、後一日上班都至少間隔 11 小時。某一側沒有班，該側就算通過。間隔用實際上下班時間，在扣休息之前。
- 接下這班後，當週有出勤的日期不超過 5 天。

三個數字的員工編號是正職。名單、查班、排行榜和這則回覆都不出現他們。今日班表會列出他們的暱稱和上下班時間。

被丟那一班的上班時間決定班別：09:00–10:59 是早班，11:00–14:59 是中班，17:00–19:59 是晚班。一個人看已讀班表裡出現最多的那段。平手，或有任何一班落在這三段以外，就是流動班別。回覆留下與被丟那一班同班別的人、中班，以及流動班別。被丟的班落在三段以外時，留下中班和流動班別。流動班別會標成「（流動班別）」。中班只列一次。沒有人符合就回「目前無合規人員可接班。」這個 LINE 帳號還沒查過自己的員工編號就按選單，會先請你輸入編號。

# 需求

- 一個 [LINE Developers](https://developers.line.biz/) Messaging API channel，要有長期的 channel access token 和 channel secret
- 一組 [Gemini API key](https://aistudio.google.com/apikey)
- 一個 Google 帳號，用來開新的 [Apps Script](https://script.google.com/) 專案。雲端硬碟檔案歸這個帳號

# 安裝

1. 在 Apps Script 專案新增 `roster.gs`、`Code.gs`，分別貼上 `gas/roster.js`、`gas/Code.js`。原本的 `Code.gs` 整份換掉。
2. 專案設定 → 顯示資訊清單，用 `gas/appsscript.json` 換掉。
3. 專案設定 → 指令碼屬性：

| 屬性 | 值 |
| --- | --- |
| `LINE_CHANNEL_ACCESS_TOKEN` | LINE 的長期 token |
| `LINE_CHANNEL_SECRET` | LINE channel secret |
| `GEMINI_API_KEY` | AI Studio 的 key |
| `GEMINI_MODEL` | 可省略。預設 `gemini-3.8-flash` |
| `ADMIN_LINE_USER_ID` | 管理員的 LINE userId。還沒填時，傳任何訊息都會回你的 userId |
| `ROSTER_FOLDER_ID` | 雲端硬碟資料夾 ID，資料夾網址裡 `folders/` 後面那一串 |

4. 選函式 `authorize` 並執行。同意外部連線、**Google 雲端硬碟**（完整 Drive，含這個應用程式以外建立的檔案），以及觸發條件。改過程式或權限後再執行一次。
5. 部署 → 新增部署 → 網頁應用程式。執行身分是你自己。存取權是「任何人」。複製網址，結尾是 `/exec`。

在 channel 的 Messaging API 分頁：

1. Webhook URL 貼上那個 `/exec` 網址，按 Verify。
2. 打開 Use webhook。
3. 關掉自動回覆和加入好友的招呼訊息，讓機器人的回覆留在畫面上。
4. 用手機加這個官方帳號為好友。

改過程式後再部署一次：管理部署 → 編輯 → 版本選「新版本」。Webhook 網址留著。貼上新的 `Code.gs` 和 `roster.gs`，再執行一次 `authorize`。

# 用法

全站共用一份目前班表。只有 `ADMIN_LINE_USER_ID` 能上傳 PDF。

| 動作 | 結果 |
| --- | --- |
| 管理員傳班表 PDF | 機器人先回已收到，讀完再傳員工名單 |
| 其他人傳 PDF 或照片 | 機器人請你輸入員工編號 |
| 加入好友，班表已經讀過 | 名單，並請輸入員工編號 |
| 加入好友，班表還是空的 | 「班表尚未更新。」 |
| 員工編號，例如 `12345` | 那個人今天和之後的班次。每一班標 `TC` 或 `FL`，只寫上下班時間。這個 LINE 帳號會記成這個編號。下週還沒讀到會寫在回覆裡 |
| `班表`，或不是編號的文字 | 再列一次名單 |
| `排行榜` | 自己的當月名次和時數，然後前五名 |
| `丟換班` | 誰能接你今天之後的班 |
| `今日班表` | 今天的 TC 和 FL。同一段上下班的人寫在同一行。正職也列在裡面 |
| 再傳一次同一份 PDF | 沿用已經存好的班表 |

底部選單在 LINE 後台設定。按鈕送出的文字是 `排行榜`、`丟換班` 和 `今日班表`。

# 設定

指令碼屬性就是設定。

- **LINE token 和 secret** 來自 Messaging API channel。用長期 token。
- **Gemini key** 來自 AI Studio。**模型**留空就用 `gemini-3.8-flash`。
- **管理員**是一個 LINE userId。先留空，傳任何訊息給機器人，再把回覆裡的 userId 貼進來。
- **班表資料夾**是雲端硬碟資料夾 ID。班表 JSON 和上傳的 PDF 會建在這裡。已經存在別處的班表，下次被讀到時會移進這個資料夾。
- **Webhook** 是網頁應用程式的 `/exec` 網址。Use webhook 保持開啟。自動回覆和加入好友的招呼保持關閉。
- **選單**是 LINE 後台的圖文選單。三顆按鈕送出 `排行榜`、`丟換班` 和 `今日班表`。
